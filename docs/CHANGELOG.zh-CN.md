# Changelog

**中文（简体）· [Português (Brasil)](../CHANGELOG.md) · [English](CHANGELOG.en.md) ·
[Español](CHANGELOG.es.md)**

vidctl 的所有重要变更，采用
[Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 格式，
[SemVer](https://semver.org/lang/zh-CN/) 版本控制，并按发布工作流为每个平台发布一个版本。

各平台的发布版本（`vX.Y.Z-windows`、`vX.Y.Z-linux`、`vX.Y.Z-macos`）共用本
changelog：它们之间的差异仅在于包的操作系统。

## [Unreleased]

暂无 — 开发中。

## [2.11.0] — 2026-10-24

- **全新品牌图标**：应用图标和网站标志从摄像机改为**居中镜头**（光圈叶片造型），沿用品牌蓝色，覆盖各安装包、favicon、网站标志以及应用初始空状态。
- **依赖更新**：`wails` 升级至 v2.17.0（含间接依赖），前端 `svelte-check` 升级至 4.7.7。

## [2.10.0] — 2026-10-18

- **主界面更简洁**：移除了页脚，顶栏只保留右侧的**“选项”**按钮（不再有居中的 “vidctl” 名称）。**ffmpeg** 状态移入菜单内部，可用时带绿色指示。拖放区域（空状态）也移入与侧栏同款设计的面板。窗口标题从 “vidctl — video compressor” 改为 **“video controller”**。

## [2.9.1] — 2026-10-18

- **修复 — 更新检查**：**AUR** 和 **RPM** 包在构建时未嵌入版本号（二进制为
  `dev`），因此检查会误判应用已是最新。现在 `PKGBUILD` 与 RPM spec 会传入
  `-ldflags -X ...internal/version.Version`，与 `.deb` 和 `.zip` 一致。并且当
  无法确定本地版本时，应用会显示**“本地版本未知”**，而不再声称已是最新。

## [2.9.0] — 2026-10-18

- **全新视觉识别**：应用的高亮蓝从偏淡的色调改为 **鲜亮蓝** —— 深色主题
  `#3b82f6`、浅色主题 `#2563eb` —— 让界面更鲜明、更专业。官网也采用同一套
  风格（深海军蓝背景、Inter + JetBrains Mono、入场动画，以及应用图标 + “vidctl”
  的品牌标志）。

## [2.8.0] — 2026-10-17

- **本地转写**（阶段 12）：通过视频菜单（“转写视频…”）应用使用 **离线**
  语音识别引擎（whisper.cpp/`whisper-cli` 或 vosk）生成 `.srt`/`.vtt` 字幕
  和纯文本 `.txt`，`auto` 会自动检测已安装的引擎。音频提取为 16 kHz 单声道
  PCM，语言可选 `auto`/`pt`/`en`，格式 `all`/`srt`/`vtt`/`txt`，支持逐词
  时间戳与 `mm:ss` 片段窗口。全部在本地运行——不上传云端；未安装引擎时应用
  会提示安装方法。任务进入同一队列（`Task.Kind = transcribe`），支持进度、
  取消和“打开文件夹”。

- **修复 — 按时间切割**：移除了每段至少 1 分钟的限制。余下部分现在会成为最后
  一段，即使不足 1 分钟（例：1:49 视频 → `1:00` + `0:49`），而不再阻止切割。
  每个视频最多 60 段的限制保留。

## [2.7.0] — 2026-10-14

- **自定义预设**（阶段 9）：除内置预设外，还可以创建、编辑和删除自己的预设——
  名称、模式（大小或 CRF）、音频码率、编码（H.264/H.265）与编码器
  （软件/NVENC/AMF/QSV/VideoToolbox）。预设保存在配置文件夹的 `presets.json`
  中（原子写入），会出现在“预设”区域并像其他预设一样压缩，使用 `custom-` 前缀
  的 ID 并带有字段校验。

## [2.6.0] — 2026-10-13

## [2.5.0] — 2026-10-12

  Linux 的 `notify-send`），并用系统文件管理器打开文件夹；通知绝不会影响转换结果。
- **代码组织**：Wails 绑定门面移入 `internal/app`（根目录只保留入口与一个固定前端

  英文、西班牙文和中文的 `README`/`CHANGELOG` 移入 `docs/`，链接与项目结构树已更新。

## [2.3.0] — 2026-10-11

- **从视频提取音频**（阶段 6）：侧边栏新增的 **“提取音频”** 部分无需重新编码即可提取音轨，可选择格式（mp3、opus、aac、flac、wav 或复制 — 流复制，仅重新封装）、质量（kbps）、声道（单声道/立体声）、EBU R128 标准化（loudnorm）和时间窗口（mm:ss）。提取进入同一个任务队列，带进度、取消以及完成后的打开文件夹。输出文件后缀可在“设置”中配置（默认 `-audio`）。
- **侧边栏名称**：“切割成段”改为 **“切割”**，“按文件调整”改为 **“视频调整”**，清晰区分哪些属于音频（提取）、哪些属于视频（缩放、切割、FPS、旋转…）
- **一次一个视频**：“添加视频…”改为 **“切换视频…”** — 切换会替换当前选择、**将按文件选项重置**为默认，且不再批量入队（应用一次只处理一个任务，串行）。
- **转换队列 → 任务队列**：队列现在列出任何任务（压缩或提取音频），并带任务计数。
- **更少冗余**：加载视频后，内容顶部的放置区域已移除 — 切换只需使用 **“切换视频…”** 按钮，或在窗口任意位置拖入新文件；该区域仅保留在空屏上。
- **更大字号**：窗口界面的每个字号都增加了 **1px**（层次保持不变；卡片和队列中的密集文字读起来更舒适）。
- **视频卡片上的“提取音频”按钮**：音频选项仍位于侧边栏，但提取按钮现在位于视频输出框下方的独立卡片中（外观与“另存为…”相同），音频路径显示所选格式的扩展名（`.mp3`、`.flac`、`.wav`…），并提供一个 **“另存为…”** 以选择其他位置。
- **更大的默认窗口**：窗口默认以 **1360×768** 打开（原为 1000×700）。
- **“目标大小”→“大小”**：侧边栏部分改为仅显示 **大小**，控件标签改为 **兆字节**（消除 MB = 兆比特的歧义）。
- **“系统”主题更可靠**：外观“系统”选项现在读取真实的桌面主题（Linux 读取 gsettings/GTK，macOS 读取 `AppleInterfaceStyle`，Windows 读取注册表），而不是信任 WebKit 的 `prefers-color-scheme`——后者在 Linux 上即使系统为深色也会报告“浅色”。

## [2.2.0] — 2026-10-11

偏好持久化、批量转换队列、大小估算、带 GPU 加速的视频编解码器和按文件调整：偏好在关闭后仍然保留，可以一次压缩多个视频，压缩前显示预期大小，**高级**卡片可切换 H.265 或硬件编码器（NVENC/QSV/AMF/VideoToolbox），每个视频都支持缩放、切割、移除音频、FPS、旋转和缩略图。

### 新增

- **大小估算**：大小模式下，“目标大小”面板显示一个徽标，标明预期输出大小 — 使用与 2-pass 编码相同的比特预算（现在统一位于 `internal/estimate`）— 并在目标更小时显示相对原始文件的节省。新增 `EstimateSize` 绑定；CRF 模式目前没有预测，徽标不会出现。
- **H.265/x265 编解码器**：步骤 02 的“高级”卡片可让每个任务选择 H.264 或 H.265；预设保持其默认编解码器。结合现有的 2-pass，大小模式现在使用 `libx265`，精度与 x264 相同（按编码器构建参数现在位于 `internal/encode`）。
- **GPU 加速（NVENC/QSV/AMF/VideoToolbox）**：硬件按任务可选（opt-in），且本机 `ffmpeg` 没有、或驱动 1 帧探测失败的端点会显示为禁用 — 新增带缓存和重新检测（“重新检查”）的 `GetEncoders` 绑定。大小模式的 GPU 使用 1-pass VBR（近似目标，±5–10%），当硬件编码器启用时 UI 会提示；软件仍是默认。
- **按文件调整**：步骤 02 新增 **“按文件调整”** 卡片，支持缩放（默认/原始/自定义）、`mm:ss` 窗口裁剪、移除音频、FPS、旋转（transpose）和编码结束时的缩略图生成。`internal/compress/adjust.go` 中的过滤器构建器按固定顺序 transpose→scale→fps，`-ss/-to` 放在 `-i` 之前，大小预算和进度基于裁剪后的时长，并带冲突校验（手动裁剪 × 分段、裁剪反向、旋转/FPS 越界）和新的 `OpenThumbnailDialog` 绑定。
- **NVENC 预设（速度 × 质量）**：启用 NVIDIA 编码器后，**高级**卡片增加按任务的 `p1`–`p7` 预设选择器（默认 `p4`，均衡）。`p1`/`p2` 几乎让视频引擎上的编码速度翻倍（引擎本身已达到 100%），大小模式下压缩效率略有损失；`p7` 优先质量。硬件编码不使用图形引擎 — 面板的“GPU %”反映图形与编码器之间的最大值。
- **可折叠侧栏**：配置卡片（`目标大小`/`质量`、`高级`、`预设`、`切割成段`、`按文件调整`）可通过其标题折叠与展开（chevron、鼠标或键盘）。`高级`、`切割成段` 和 `调整` 默认 **关闭**，减少视觉杂乱；状态在会话内有效。
- **总转换用时**：队列中的每个任务在处理期间实时显示已用时间，完成时显示**总计**（进度卡、队列行和结果卡）— 便于对比预设和编码器（软件 × GPU、NVENC `p1`–`p7`）。
- **主窗口拖放**：内容新增放置目标区域，显示“将视频拖到此处”+ **“打开视频…”** 按钮，即使已加载视频也可见 — 拖入文件会切换输入，拖入多个则入队（复用 `wails:file-drop`）。
- **本地调试模式**：`VIDCTL_DEBUG=1 ./build/bin/vidctl` 会在终端开启日志，记录队列转换、发出/收到的事件（以及因状态被丢弃的补丁）、`Compress`/`GetTasks` 调用和前端 JS 异常 — 用于诊断进度 UI，而不影响正常运行（默认关闭）。
- **转换队列（批量）**：“添加视频…”一次入队多个文件（或在窗口拖入多个），每个文件一个任务，使用当前预设和输出；队列替代步骤 04 显示名称、预设、状态、正在运行项目的进度条、按项目取消和“清空队列”。新增 `compress:queued`/`compress:start` 事件，前端按 `JobID` 路由：某个项目出错不会拖垮其他项目。新增绑定：`CompressMultiple`、`GetTasks` 和 `ClearFinished`。
- **持久化配置**：预设、MB 大小、CRF 和输出文件夹在下次启动时恢复原样。文件位于 `<config-dir>/vidctl/config.json`（Linux `~/.config`、macOS `~/Library/Application Support`、Windows `%AppData%`），采用原子写入，崩溃不会损坏。文件缺失或无效时应用以默认值打开，而不是失败。
- **设置 → 程序文件**：可将 `ffmpeg` 和 `ffprobe` 指向 PATH 之外的字段。配置的路径优先于 PATH，立即生效（无需重启），无效路径会报错，而不是静默回退到 PATH 中的二进制。
- **设置 → 输出**：输出文件夹字段；留空则保持在原视频旁保存。

### 变更

- 侧边栏改为**圆角面板**（GNOME/浮动面板风格）：与内容同色，带柔和描边（`18px` 圆角）和细微阴影，取代了带完整分隔线的“方柱”列 — 现在通过间距和圆角分隔，阴影按主题（浅色/深色）定义，且不依赖系统。
- 侧边栏**滚动条**由 UI 自定义：本机滚动条（GTK/WebKit）已隐藏 — 不再逸出面板，也不会在悬停时覆盖内容。自定义细条（`8px`、内缩）在滚动/悬停/拖动时出现，静止约 0.8 秒后淡出，三个平台行为一致。
- 进度卡跟随队列中选中的项目，取消改为按项目 — 该操作不再停止整个任务。
- `maxParallel` 现在生效：定义一次同时压缩多少个视频（默认 **1** = 串行），在启动和保存“设置”时应用。
- `CheckFFmpeg`、`GetMediaInfo` 和缩略图现在遵循配置的二进制路径，并分别提供“不在 PATH 中”和“你配置的路径不可用”的提示。
- `language`、`notifyOnDone` 和 `openFolderOnDone` 字段已保留在文件中，但只有在对应功能存在时才生效（未来的计划阶段）。
- 调试模式（`VIDCTL_DEBUG=1`）现在跟踪**外部命令和流程决策**：完整的 `ffmpeg` 命令（2-pass、单遍和缩略图）、按片段的编码器/硬件选择（`encoder=hevc_nvenc`、2-pass、`-vf` 链、seek、移除音频、FPS、旋转）、`ffprobe` 和缩略图（`[media]`），以及编码器列表/探测（`[encode]`，端点失败时带原因）。每个命令都可逐行复现。

### 修复

- 当 `ffmpeg` 列出某个端点但 1 帧探测失败时（例如无 AMD GPU 的 `h264_amf`），编码器检测不再卡住文件选择：`codecs` 在 JSON 中曾为 `null`，前端在构建编码器列表时崩溃。现在检测始终返回一个列表（无编解码器时为空），前端也容忍 `null`。
- 进度面板的 **“GPU %”** 之前只测量 `utilization.gpu`（图形/计算），NVENC 编码期间约为 0 — 视频编码加载的是**编码器**引擎（`utilization.encoder`），而非图形条。收集器现在报告**两者中的最大值**，因此面板能真实反映硬件编码。
- 硬件编码器探测改用 `256×256` 帧：之前的 `64×64` **低于 NVENC 的最小尺寸**（“Frame Dimension less than the minimum supported value”），因此即使驱动正常，现代 NVIDIA GPU 也会显示为“已检测到但未运行”。
- 按平台端点：**AMF（AMD）** 仅在 Windows 提供，**VideoToolbox** 仅在 macOS 提供；NVENC 和 QSV 在任何操作系统上都会检测，**软件**/“自动”始终可用。此外，探测失败的原因现在显示在 UI（**高级**卡片）中，而不是通用文本。
- **拖放**在三个平台均可用：应用不仅监听 `wails:file-drop`，还注册运行时 `OnFileDrop`（连接 WebView 的 drop 监听器）。在 **Linux** 上，Wails 原生处理器会让 WebKit 导航到被拖入的文件（视频会“播放”，UI 消失），因此在那里路径改从 DOM 本身（`text/uri-list`）读取而不导航；Windows/macOS 继续使用 Wails 原生拖放。整个窗口都是拖放区域，拖动时**屏幕四周出现虚线轮廓**指示放置位置。
- **输出与缩略图默认与源同目录**：未保存目标文件夹时，建议路径曾指向应用的工作目录（缩略图文件“消失”，让在视频旁查找的人找不到）。现在默认是源视频所在文件夹（或“设置”中配置的文件夹）。
- 生成的**缩略图**使用视频**开始后 5 秒**的帧（第一个片段），而非最后一段的中间 — 分段切割时曾落在接近结尾处，看起来像“最后一帧”；同时也避免开头黑屏。短视频（低于 10 秒）回退到中间。

## [2.1.0] — 2026-09-27

采用 Constrict 风格的视觉重设计，支持拖放、缩略图和计数器微调。

### 新增

- **Constrict 风格视觉**：哑光深色主题（带石板蓝强调色的最新令牌）、派生浅色主题，以及 Linux/Windows/macOS 安装包中的自定义图标；双栏布局（设置侧栏 + 视频区域）、按组卡片，以及“设置”模态框（系统/浅色/深色主题和 ffmpeg 重新检查）。
- **拖放**：将视频拖入窗口即可选中；悬停时空白区域高亮（`--wails-drop-target`、`wails:file-drop` 事件）。
- **缩略图**：视频行显示通过 ffmpeg 提取的帧（在 `min(1s, dur/2)` 处查找，限制 320px），按 path+size+mtime 缓存在 `os.TempDir()/vidctl-thumbs`；新增 `GetThumbnail` 绑定。
- **可编辑且支持微调的计数器**：点击数字输入（Enter/点击外部确认、Esc 取消、支持逗号），按住 **Shift** 配合 `+/−` 箭头（或 `↑/↓`）可使用 0.1 的精细步进。
- **每段分钟端到端支持小数**：`split.Spec.MinutesEach` 从前端到切割均接受小数（`1.5` = 1 分 30 秒），并有经过测试的 `internal/split` 层。
- **视频行菜单（⋮）**：切换文件 / 清空。

## [1.0.17] — 2026-09-13

vidctl 的首个 **production ready** 版本。

### 新增

- 按平台预设压缩视频：WhatsApp 状态（10 MB）、WhatsApp（16 MB）、Instagram（16 MB）、Shorts（30 MB）、YouTube（CRF）或用户自定义自由大小（2–100 MB）。
- ffmpeg **2-pass** 编码，精确命中最大大小且不超过所选限制。
- 按阶段实时进度（pass 1/2 和 pass 2/2），可随时取消。
- 启动时验证 `ffmpeg`/`ffprobe`，并提供“重新检查”按钮重新读取系统 PATH — 可在应用打开时安装 ffmpeg，无需重启。
- 支持 **Linux、Windows、macOS** 原生桌面（Wails v2 + WebKit/WebView2）。
- 离线模式：字体和界面嵌入二进制。
- 按平台打包（.zip、.deb 和 .rpm），并发布 `checksums.txt`，在所有发布版中核实。
- 默认缩放最大宽度 1280 px，保留视频宽高比。

### 修复

- Windows：转换和文件探测不再弹出控制台窗口（`CREATE_NO_WINDOW`）。
- Windows：“重新检查”无需重启即可检测到新安装的 ffmpeg/ffprobe（在注册表中重读用户/机器 PATH）。
- 发布的 .zip 包不再包含整个项目资源树。

### 规格

- Go 1.25+、Wails v2.15、Svelte 5，系统需要 ffmpeg/ffprobe。
- 每个发布版只发布其操作系统的包（Windows：`.zip`；Linux：`.zip`、`.deb`、`.rpm`；macOS：包含 `vidctl.app` 的 `.zip`）。
